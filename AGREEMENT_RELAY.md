# Agreement draft relay

PoolBrain's account UI currently exposes one endpoint, already used by this SMS service. Preserve that endpoint and its Alert Triggered subscription.

This change routes customer.created events from the existing authenticated, durable inbound queue to the fixed Tampa VIP agreement app. The existing signing secret authenticates the forwarded envelope. No SMS/email jobs are generated by the relay. Failures enter existing bounded retries and dead-letter monitoring; alert events retain their existing processing path.

Activation order:
1. Deploy this change to the SMS service with AGREEMENTS_DRAFT_RELAY_ENABLED absent/false. No migrations or new dependencies are needed.
2. In the agreement app, configure the same PoolBrain company ID and signing secret securely, and enable automatic drafts. Do not paste the secret into chat.
3. Set AGREEMENTS_DRAFT_RELAY_ENABLED=true on the existing SMS worker/service using its normal deployment configuration.
4. Enable Customer Created in PoolBrain. Keep Alert Triggered and the existing endpoint URL unchanged.
5. Verify a new customer event reaches the queue, generates one draft per address, and creates no messages. Check existing alert processing separately. No production verification has occurred yet.

Rollback: disable Customer Created in PoolBrain, then disable the relay flag. Existing agreement drafts remain. Investigate/replay pending or dead-letter customer events after recovery rather than treating them as completed. Never change the existing SMS webhook destination.

Validation: 14 targeted relay/worker tests passed locally using mocked requests; no real customer traffic or production setting changes. Tests cover signed delivery, destination pinning, disabled configuration, response failures, timeout retry, customer-only dispatch, and continued processing after relay failure.
